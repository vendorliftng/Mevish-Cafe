# Implementation Plan: Replication + New Features

This is a large plan divided into **6 phases**. Each phase is self-contained and can be tested independently before moving to the next.

---

## Phase 1: Config-Driven Architecture (Replication Foundation)

**Goal:** Make the entire system replicable by editing ONLY `config.js` — no hardcoded values in any HTML file.

### 1A. Upgrade `config.js`
- Add new fields to `CONFIG.RESTAURANT`: `fullAddress` (street-level), `locale` (`"en-NG"`), `cuisineTypes` (array), `seatCount`, `slug` (for localStorage keys, e.g. `"mevish"`), `featuredItems` (array of 6 item names to show on homepage), `mapsEmbedUrl` (the full Google Maps embed pb URL), `kitchenWhatsapp` (separate WhatsApp number for kitchen notifications, falls back to `whatsapp`)
- Add `CONFIG.STORAGE_PREFIX` = `CONFIG.RESTAURANT.slug + "_"` to replace all hardcoded `mevish_` localStorage keys
- Change `formatCurrency()` to use `CONFIG.CURRENCY` + `CONFIG.RESTAURANT.locale` instead of hardcoded `₦` and `en-NG`
- Update `RECEIPT_FOOTER` template to use template literals with CONFIG values
- Make `FALLBACK_MENU` empty `[]` — restaurants should always load from API. If API fails, show "Menu unavailable" with a retry button
- Remove "Mevish Pizza" branding from fallback

### 1B. De-hardcode `index.html` (~15 changes)
- Replace title/meta `Mevish Eatery` → set dynamically via JS from CONFIG
- Replace `#logo-text` → `CONFIG.RESTAURANT.name`
- Replace hero greeting → `"Welcome to " + shortName` (first word of restaurant name)
- Replace Google Maps link (line 790) → construct from `CONFIG.RESTAURANT.GOOGLE_PLACE_ID` using `https://www.google.com/maps/search/?api=1&query=Google&query_place_id=PLACE_ID`
- Replace hardcoded Maps embed URL (line 1611) → use `CONFIG.RESTAURANT.mapsEmbedUrl`
- Replace currency fallback → `CONFIG.formatCurrency(n)`
- Replace all `'Mevish Eatery'` fallback strings → `CONFIG.RESTAURANT.name || 'Restaurant'`
- Replace `mevish_menu_cache` → `CONFIG.STORAGE_PREFIX + 'menu_cache'`
- Make fallback reviews generic (remove "Yola" references)

### 1C. De-hardcode `home.html` (~50+ changes — biggest file)
- Title, meta tags, og tags, Schema.org JSON-LD: all set dynamically via JS on page load
- Hero: brand name, eyebrow, subtitle — all from CONFIG
- Featured menu cards: dynamically generated from `CONFIG.RESTAURANT.featuredItems` or API
- About section, contact section, footer: all CONFIG-driven
- Fix `© 2025` → `© ` + `CONFIG.RESTAURANT.year`

### 1D. De-hardcode all other HTML files
- **dashboard.html:** title, meta, PIN gate/header brand, receipt fallbacks, `en-NG` locale
- **manager.html:** title, meta, PIN gate/sidebar brand, `₦` form labels, `en-NG` locale
- **menu-board.html:** title, brand, fallback, locale
- **track.html:** title, meta, brand, fallback
- **blog.html:** title, meta, og, Schema.org, navbar, subtitle, footer, locale, copyright year, demo content
- **blog-admin.html:** title, PIN gate brand, default author
- **article.html:** title, og, navbar, footer, copyright year, demo content, WhatsApp share text

### 1E. Create `SETUP-GUIDE.md`
- Simple doc: copy repo → edit config.js → create Google Sheet → deploy Code.gs → update API_URL → push to GitHub Pages

## Phase 2: Customer Phone & Loyalty System

**Goal:** Require phone number on every order, track loyalty points, reward repeat customers.

### 2A. New Google Sheet: "Customers"
Columns: Phone, Name, Total Orders, Total Spent, Loyalty Points, Last Visit, Created At

### 2B. New Code.gs endpoints
- **GET `type=customer&phone=...`**: Lookup single customer
- **GET `type=customers`**: Return all customers
- **GET `type=loyaltyReward&phone=...`**: Check if customer qualifies for a reward

### 2C. Modify `newOrder` action in Code.gs
- Accept new field `customerPhone`
- After writing order row, look up or create customer in Customers sheet
- Increment Total Orders and Total Spent
- Award 1 point per order; 10 points = 1 free item reward
- Return `{..., loyaltyPoints, nextRewardAt}` in response

### 2D. Update `index.html` order modal
- Add phone number input (required, validated as Nigerian format)
- Appears before customer name field
- Included in POST payload

### 2E. Success screen loyalty display
- Show points earned and progress to next reward
- If reward earned: "🎉 FREE item earned! Show cashier: REWARD-XXXX"

### 2F. Manager: Customers tab
- New sidebar tab "Customers" in manager.html
- Table: Phone, Name, Orders, Total Spent, Points, Last Visit
- Search by phone, view order history

## Phase 4: WhatsApp Notifications (Free, no API cost)

**Goal:** Both customer and restaurant use `wa.me` links — zero API cost, zero external services.

### 4A. Customer → Restaurant (on order placed)
- On the **success screen** in `index.html`, add a WhatsApp button: **"Send Order to Kitchen via WhatsApp"**
- Opens `wa.me/{CONFIG.RESTAURANT.kitchenWhatsapp}?text=...` with pre-filled message:
  ```
  🛎️ New Order!
  Order: ORD-XXXX-XXXX
  Customer: Name (Phone: 080xxx)
  Items: 2x Jollof Rice | 1x Chicken
  Total: ₦6,000
  Table: T5
  ```
- The customer taps it → WhatsApp opens on THEIR phone with the restaurant's number pre-selected and the order details pre-filled → they just hit Send
- This directly notifies the kitchen/manager's WhatsApp

### 4B. Customer → Restaurant (from tracking page)
- On `track.html`, add a WhatsApp button: **"Message Restaurant"**
- Opens `wa.me/{CONFIG.RESTAURANT.kitchenWhatsapp}?text=Hi, I'm waiting for my order ORD-XXXX-XXXX`

### 4C. Dashboard (forward/share)
- On each order card in `dashboard.html`, add a small WhatsApp icon
- Opens `wa.me/?text=...` letting the cashier forward the order to any contact (e.g. a delivery driver)
- Pre-fills the order summary text

### 4D. config.js addition
- Add `CONFIG.RESTAURANT.kitchenWhatsapp` (can be same as `whatsapp` or a separate kitchen number)

## Phase 5: Customer Reviews & Ratings

**Goal:** Collect star ratings + comments after order completion.

### 5A. New Google Sheet: "Reviews"
Columns: Timestamp, Order ID, Phone, Rating (1-5), Comment, Customer Name, Status (Approved/Pending)

### 5B. New Code.gs endpoints
- **POST `action=saveReview`**: Save review
- **GET `type=reviews&status=approved`**: Get approved reviews
- **POST `action=approveReview`**: Manager approves/rejects a review

### 5C. Track page: Review prompt
- When status is "Paid" → show star rating (1-5) + comment field + Submit button
- Pre-fill phone from order data

### 5D. Update index.html reviews section
- Fetch real approved reviews from API instead of hardcoded fallbacks
- Fix "Leave a Review on Google" link → construct from `CONFIG.RESTAURANT.GOOGLE_PLACE_ID`

### 5E. Manager: Reviews moderation tab
- New "Reviews" sidebar tab in manager.html
- Approve/reject pending reviews
- Show average rating

## Phase 6: Analytics Dashboard Enhancements

**Goal:** Richer analytics in the manager panel.

### 6A. New Code.gs endpoints

- **GET `type=categoryBreakdown&days=30`**: Revenue by menu category
- **GET `type=topCustomers&days=30`**: Top 10 customers by spend

### 6B. Update manager.html

- **Category Performance**: Doughnut chart by category
- **Customer Leaderboard**: Top 10 customers table
- **AOV Trend**: Line chart using dailyRevenue data
